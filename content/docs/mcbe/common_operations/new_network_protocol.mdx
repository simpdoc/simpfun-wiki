---
title: "NethetNet 网络协议相关问题"
---

Minecraft 基岩版 1.26.50 起，联机传输层从 RakNet 切换到了 NetherNet（基于 WebRTC 的 P2P 传输）：

- 信令走 BDS 的 HTTP 端口（`server-port`，TCP），客户端 POST SDP offer，BDS 返回 answer；
- 游戏数据走 WebRTC DataChannel（DTLS/SCTP over UDP），**每个玩家连接由 BDS 分配独立的 UDP 端口**（`server-udp-ports`）。

在端口受限的 NAT 服务器和面板服上，只放行了有限端口，NetherNet 的"每玩家一个 UDP 端口"模式直接崩坏：第一个玩家占掉唯一端口后，第二个玩家无法加入。

在当前版本（26.60），旧版的 RakNet 协议仍能使用。

## 继续使用 RakNet 协议

我们建议在 RakNet 协议被彻底弃用前继续使用 RakNet 协议。

在服务器文件管理根目录找到 `server.properties` 文件并打开，在其中找到这一行：

```properties title="server.properties"
transport=nethernet
# Which transport protocol the server should use.
# Allowed values: "raknet" or "nethernet"
```

把 `nethernet` 改成 `raknet` ，以便继续使用 RakNet 网络协议。

## 未来的版本该怎么办

LeviLamina 与 Endstone 已经实现了 NetherNet 的单端口复用。开启后，一条 TCP 信令隧道 + 一条 UDP 媒体隧道即可支撑多名玩家同时在线，不再需要“一人一端口”。

同时，Java 版的 Geyser 互通插件也实现了 NetherNet 协议的支持。

因此我们建议，有条件的服主可以选择使用 Endstone 服务端，或者直接转向 Java 版服务器+ Geyser 的组合配置。
